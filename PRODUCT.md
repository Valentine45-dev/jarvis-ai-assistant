# Product

## Register

product

## Users

Valentine — sole developer and operator. Power user with full mental model of the system. Interacts with JARVIS daily as a personal OS controller: issuing commands by voice or text, monitoring system state, managing automations. Context is always the same: at the desk, focused, expecting the system to respond without hand-holding.

Future state: possibly shared with a small set of technical users who self-select into the tool. Design decisions made now should not require retrofit for that audience — they will be equally capable, equally uninterested in being coddled.

## Product Purpose

JARVIS is an AI-powered personal operating system assistant. It converts natural language into executable system commands: opening apps, running code, controlling the browser, managing files, automating workflows. It is not a chatbot. It does not converse. It executes.

Success looks like: the user issues a command and the system acts — correctly, immediately, with no friction. The UI communicates state, not personality. The experience feels like operating a piece of precision equipment, not talking to a product.

## Brand Personality

**Precise. Commanding. Inevitable.**

JARVIS does not need to be liked. It needs to be correct. The tone is that of a British butler — competent subordination, not friendly collaboration. It never apologizes. It confirms, executes, and reports. When it fails, it names what failed and why, without softening.

The interface extends this personality: no rounded corners softening a hard edge, no animations that suggest warmth, no copy that hedges. The system is always in control of itself, always certain of its state.

## Anti-references

**Cortana (Windows 11):** Rounded UI, friendly tone, apologetic failure states, designed to be liked. Everything JARVIS is not. Cortana is a friend. JARVIS is a butler. A butler does not need the user's approval — he needs to be correct.

**Generic AI chatbot UIs:** Conversational bubble layouts, avatar-driven interaction, "thinking..." indicators with personality. JARVIS is a system controller, not a conversation partner. Any UI that reads as "chat" is wrong.

**Gaming overlays (neon excess):** High-chroma color saturation, aggressive glow effects, decoration for its own sake. JARVIS uses color to carry meaning, never to impress.

## Design Principles

1. **Competence over likability.** The interface never apologizes, never hedges, never softens. Failure is named precisely. Success is confirmed concisely. No filler copy.

2. **Inevitable execution.** Routine actions don't feel like requests — they feel decided. The UI informs rather than asks permission. Confirmation exists only for genuinely destructive actions, and even then it feels like a final check, not a second-guess.

3. **Signal without noise.** Every visual element carries load. Color appears only to mean something: cyan = active, emerald = success, red = error, gold = idle. When nothing is happening, the UI is quiet — not blank, but still.

4. **Butler hierarchy.** The system is subordinate to the user's will but never uncertain about its own state. It knows what it's doing. The user knows what it's doing. No ambiguity is left unresolved.

5. **Restraint as craft.** The sci-fi HUD aesthetic is earned through precision, not spectacle. Sharp edges, monospace data, controlled animation. Anything decorative that does not also function is removed.

## Accessibility & Inclusion

Current: personal tool, no formal WCAG requirement. Minimum bar: text must be readable in ambient light without strain (≥4.5:1 contrast for body text). No accommodation for reduced motion currently implemented.

Future: if shared, target WCAG AA. The existing color system (high-chroma cyan on near-black) is structurally compatible — opacity values need lifting (minimum 0.75 for secondary text).
